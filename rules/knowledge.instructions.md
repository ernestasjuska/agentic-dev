# Knowledge

Rules, skills and memory carry what you can't know or find out yourself: this machine,
these projects, my preferences, conventions private to my organisation. A public
convention you already know doesn't belong in them. Neither does anything you can find
in public docs or by trying it.

Don't trust your sense of what you already know. Test it. When an instruction shapes
your work and you suspect you would have done the same without it, give the same task to
a fresh context twice: once without the instruction, once with it cut to one line.
Check both outputs against the constraint the instruction exists to enforce. Your own
context can't run this test, because the instruction is already loaded there.

- Holds without the instruction: propose deleting it.
- Holds with the one-line version: propose cutting it to that line. Often that line is
  just a choice between behaviours you already know, like "LF line endings" or
  "squash merges".
- Fails both: keep the full text.

Report the task, the constraint, and whether each run met it. If the instruction is
wrong or out of date, propose the fix.

When you learn something private, such as a convention read from past commits, a path I
mention or a correction, propose adding it to a rule or skill so the other agents get
it too. Memory is only for state that ends with the task.
